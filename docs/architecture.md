# 海钓潮汐小程序技术实现框架

## 1. 技术选型

首版建议采用 **微信原生小程序**，原因如下：

- 交付最快，适合验证产品方向。
- 不依赖复杂构建链路，便于后续小团队维护。
- 与微信登录、收藏、分享、订阅消息等能力天然适配。

后续如果团队要同时覆盖 H5 / App，可升级为 Taro 或 uni-app，但 MVP 不建议一开始就增加框架复杂度。

## 2. 前端结构

```text
app.js / app.json / app.wxss
pages/
  home/         首页决策
  spots/        钓点详情
  planner/      出钓计划
  profile/      我的与商业化
services/
  tideService.js
  spotService.js
data/mock/
  home.js
  spots.js
utils/
  format.js
```

## 3. 分层设计

### 展示层

- `pages/home`：负责首页聚合展示。
- `pages/spots`：负责单钓点详情和潮汐时间轴。
- `pages/planner`：负责未来计划与多钓点对比。
- `pages/profile`：负责收藏、会员和合作入口。

### 服务层

- `tideService`：统一输出潮汐与海况数据。
- `spotService`：统一输出钓点列表、详情、收藏状态。

这样做的好处是：首版可以读本地 mock，后续替换成真实 API 时不用大改页面逻辑。

### 数据层

当前使用本地 mock 数据，后续可切到：

- 第三方潮汐/天气/海浪数据源
- 自建钓点与商家数据库
- 微信云开发或独立后端接口

## 4. 推荐后端架构

### 阶段一：微信云开发

适合快速验证：

- 云函数：聚合潮汐、天气、海浪接口
- 云数据库：钓点、收藏、渔获记录、商家
- 云存储：钓点图片、分享海报

### 阶段二：独立服务化

当数据量和商业化提升后，建议升级为：

- API 网关
- 用户服务
- 钓点服务
- 海况聚合服务
- 推荐服务
- 商家服务

## 6. 推荐算法雏形

海钓指数可先使用轻量规则引擎：

- 潮汐窗口权重
- 风速权重
- 浪高权重
- 天气权重
- 月相权重
- 历史钓点偏好权重

输出：

- 总分
- 风险等级
- 推荐玩法
- 推荐时段

首版不必上机器学习，规则引擎足够可解释，也更适合用户建立信任。

## 7. 商业化技术预留

- 会员状态字段
- 商家卡片配置化
- 钓点广告位动态下发
- 分享追踪参数
- 城市包和钓点包配置化

## 8. 实施建议

### 第 1 周

- 完成产品原型
- 搭建小程序骨架
- 用 mock 数据串首页和详情

### 第 2 周

- 接入真实定位与收藏
- 完成海钓指数规则
- 打通分享能力

### 第 3-4 周

- 接真实潮汐/海况接口
- 上线首批城市钓点
- 开始内测和用户访谈
